# Content Philosophy — FX Post Engine

## Core Principle

**Data is variable. Templates are stable.**

The data layer (`lib/fx/`) owns the numbers, dates, and text. The template layer (`components/`) owns the layout, typography, spacing, and color. They must never know about each other's implementation details.

---

## Data Layer Ownership

The data layer is responsible for:

| Concern | Owner | File |
|---------|-------|------|
| Currency list (what to track) | Data | `lib/fx/currencies.ts` |
| Rate fetching | Data | `lib/fx/fetch-rates.ts` |
| % change calculation | Data | `lib/fx/calculate-movers.ts` |
| Orchestration (fetch + calculate + date) | Data | `lib/fx/load-fx-movers.ts` |
| Date formatting (PHT) | Data | `lib/fx/pht-date.ts` |
| Caption text | Data | `lib/fx/caption.ts` |
| Screenshot rendering | Data | `lib/fx/screenshot.ts` |

The data layer produces typed outputs. It does not import from `components/`.

---

## Template Layer Ownership

The template layer is responsible for:

| Concern | Owner | File |
|---------|-------|------|
| Card layout | Template | `components/FxMoverCard.tsx` |
| Card typography | Template | `components/FxMoverCard.tsx` |
| Full post preview layout | Template | `components/FxPostTemplate.tsx` |
| Colors, spacing, borders | Template | Both component files |

The template layer receives typed props. It does not call any `lib/fx/` functions directly.

---

## Data Flow

```
Frankfurter.dev API
    ↓
fetch-rates.ts (FxRatesResponse)
    ↓
calculate-movers.ts (FxMover[])
    ↓
load-fx-movers.ts (orchestrator)
    ↓
app/fx-card/page.tsx (Server Component — bridges data → template)
    ↓
FxMoverCard.tsx (receives props, renders HTML)
    ↓
Playwright screenshot → public/generated/fx-mover-{rank}-{date}.png
    ↓
Facebook Graph API (postToFacebook)
```

The bridge between data and template always lives in the route (`app/fx-card/page.tsx`, `app/fx-post/page.tsx`). Never in the component, never in the lib.

---

## The FxMover Type

This is the canonical data shape that flows from the data layer to the template layer:

```typescript
type FxMover = {
  code: string;               // ISO 4217 currency code (e.g. "USD")
  currentRateToPhp: number;   // 1 unit of currency = N PHP (today)
  previousRateToPhp: number;  // 1 unit of currency = N PHP (previous trading day)
  changePercent: number;      // % change (positive = currency strengthened vs PHP)
  direction: "up" | "down";   // direction of movement
};
```

This type is defined in `lib/fx/calculate-movers.ts` and imported by components via `@/lib/fx/calculate-movers`.

---

## Caption Ownership

The caption is **data-owned**, not template-owned. It is:
- Generated by `lib/fx/caption.ts`
- Displayed as editable text in `app/page.tsx`
- Sent to Facebook as the post `message` field

The caption is not part of the card image. It is separate text that the operator can review before posting.

## AI Content Rules

- AI may generate, refactor, or improve any code in `lib/fx/` (data layer)
- AI may generate, refactor, or improve any code in `components/` (template layer)
- AI **must not** change contact info in `lib/fx/caption.ts` without explicit user instruction
- AI **must not** change the hashtag set without explicit user instruction
- AI **must not** change card dimensions (1080×1080 for FxMoverCard) without updating TEMPLATE_GUIDE.md
- AI **must not** add new currencies to `currencies.ts` without explicit user instruction
- AI **must not** change the FxMover type's field names without updating all callers

## Schema Validation Rules

### FxRatesResponse (from Frankfurter.dev)
```typescript
{
  date: string;       // "YYYY-MM-DD" — the actual market date for this data
  base: "PHP";        // always PHP
  rates: Record<string, number>; // currency code → units of that currency per 1 PHP
}
```

Note: `rates` values are in `{currency}/PHP` format (how many units of the foreign currency equal 1 PHP). The calculation in `calculate-movers.ts` inverts this: `1 / rate` = PHP value of 1 unit.

### FxMover (derived)
- `changePercent` can be negative (currency weakened vs PHP)
- `direction: "up"` means the foreign currency gained value against PHP (costs more PHP to buy)
- Sorted by `Math.abs(changePercent)` descending — largest movers first regardless of direction

### Date Strings
- Internal format: `"YYYY-MM-DD"` (ISO 8601) throughout lib/fx/
- Display format: goes through `formatPhtDate()` in `pht-date.ts`
- Never pass raw ISO strings to components — always format via `pht-date.ts` first
